# Эталонные наборы

Здесь лежат наборы документов с известными ответами. По ним `docflow eval` измеряет качество извлечения.
Настоящие документы содержат персональные данные: в git попадает только этот файл (см. `.gitignore`).

## Формат

`evals/<slug>/<кейс>/` — одна папка на документ. `<slug>` — slug встроенной схемы (`invoice_ru`, `upd_ru`, `passport_ru`).
В кейсе лежат страницы документа и `expected.json` с правильными значениями.

```
evals/
  invoice_ru/
    schet-001/
      1.jpg
      2.jpg          # страницы сортируются по числу в имени: 1, 2, ... 10
      expected.json
    schet-002/
      1.jpg
      expected.json
```

Допустимые файлы страниц: jpg, png, pdf, tif, webp. Кейс без `expected.json` пропускается с предупреждением.

## expected.json

Ключи — имена полей схемы. Эталон может быть частичным: оцениваются только перечисленные поля.
Даты — `ГГГГ-ММ-ДД`, числа — числами, отсутствующее значение — `null`. Таблица — массив строк по порядку.

```json
{
  "number": "15",
  "issued": "2026-03-05",
  "supplier_inn": "7707083893",
  "buyer_inn": null,
  "items": [
    {"name": "Болт М8", "qty": 10, "unit": "шт", "price": 12.5, "amount": 125.0}
  ],
  "total": 125.0
}
```

Правила сравнения: строки без учёта регистра, лишних пробелов и «ё»/«е»; числа с допуском 0,01;
даты как ISO-строки; таблицы построчно по позиции, лишние и недостающие строки считаются ошибкой.

## Запуск

```
docflow eval evals/invoice_ru --extractor claude
docflow eval evals/invoice_ru --extractor fake --fake-responses ответы.json   # без модели
```

Главная метрика — `ok_precision`: среди документов со статусом `ok` доля тех, где все поля верны.
Ложный `ok` — главная ошибка, которую мы не должны допускать. Также печатаются `ok_rate`, `overall_accuracy`,
точность по полям (худшие первыми), токены и стоимость. Отчёт пишется в `evals/eval-report.json` (`--out` меняет путь).
