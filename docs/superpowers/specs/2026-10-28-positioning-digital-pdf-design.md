# DocFlow — новое позиционирование сайта и цифровая версия документа

Источник — указания пользователя от 28.10.2026 (уточняющие вопросы он просил не задавать):

> Сайт должен делаться будто продукт уже готов; выстроить логику и маркетинг так, чтобы клиент захотел взять
> аудит. Основная задумка — автовыгрузка и распределение по системам: 1С, CRM, таблицы Excel / Google и тому
> подобное. Дополнительная функция — скачать документ с фото как PDF: не фото, а PDF с цифровой версией
> документа, который сфотографировали.

## Позиционирование (меняет блоки лендинга из спецификации 2026-10-28-website-mvp-design.md)

**Главное обещание:** «Сфотографировали документ — данные уже в вашей 1С, CRM и таблицах». DocFlow — это
не распознавалка, а конвейер: принять документ из любого канала → прочитать и проверить → разложить по системам
клиента по правилам. Цифровая копия документа в PDF — приятный бонус, а не суть.

**Путь посетителя:** узнал свою боль (перенабор, ошибки в 1С, документы гуляют по мессенджерам) → увидел, куда
уходят данные (свои системы) → понял, как распределяется (правила) → поверил (проверки, честный замер, 152-ФЗ)
→ понял, что внедрение простое (аудит → пилот → подключение) → оставил заявку на аудит.

**Блоки лендинга (новый порядок):**
1. Первый экран: обещание выше; подзаголовок про счета, накладные, УПД, акты, заказ-наряды → 1С, Битрикс24,
   amoCRM, Google Таблицы, Excel; визуальная схема «документ → DocFlow → системы»; CTA «Получить аудит».
2. Боль: перенабор, опечатки в учёте, документы теряются в чатах и почте, сотрудник занят не тем.
3. Куда уходят данные (ядро): 1С (типовые конфигурации — Бухгалтерия, Управление торговлей, УНФ: документы
   поступления/реализации, контрагенты, номенклатура), CRM (Битрикс24, amoCRM: сделки, контакты, поля),
   Google Таблицы и Excel (строка на документ, позиции отдельным листом), ваша система (API, вебхуки),
   уведомления (почта, Telegram). Подача — как готовая услуга: «подключаем на внедрении», без пометок «скоро».
4. Распределение по правилам: тип документа → система; контрагент → ответственный/воронка; сумма выше порога
   → согласование; спорное → оператору. Подача: настраиваем на внедрении под ваш процесс.
5. Как это работает: каналы входа (фото с телефона, скан, PDF, почта, Telegram) → распознавание и проверка →
   выгрузка по правилам.
6. Проверки: «в 1С не попадёт ошибка» — реквизиты, суммы, даты, справочники; сомнение — оператору.
7. Цифровая копия документа: ровный PDF, набранный заново по распознанным данным, плюс исходный скан с
   текстовым слоем — для архива, отправки контрагенту, печати.
8. Ниши: для каждой — что приходит и куда уходит (пример: зуботехническая лаборатория — заказ-наряды от клиник
   → 1С и таблица взаиморасчётов с клиниками).
9. Измерено: факты прогона 28.10.2026 (как сейчас на сайте, с пометкой облачного режима).
10. Данные и 152-ФЗ: облако или сервер клиента.
11. Внедрение: аудит (что получит клиент: карта документооборота, схема выгрузки в его системы, оценка
    экономии времени) → пилот на его документах с замером точности → подключение.
12. Вопросы (FAQ) — про 1С, CRM, таблицы, сроки внедрения, безопасность, цену («после аудита»).
13. Форма аудита: + поле «Куда выгружать данные» (несколько вариантов: 1С, Битрикс24, amoCRM, Google Таблицы,
    Excel, своя система, пока не знаю).

**Решения исполнителя (можно оспорить):**
- Интеграции подаются как услуга внедрения («подключаем»), без «скоро». Выдуманных клиентов, отзывов, логотипов
  клиентов, цифр экономии и цен по-прежнему нет — это остаётся анти-целью.
- «Аудит без обязательств» — формулировка допустима; срок и стоимость аудита — плейсхолдеры, если нужны.
- Логотипы систем (1С, Битрикс24, amoCRM, Google, Excel) не используются: товарные знаки; только названия
  текстом в нашем стиле.

## Цифровая версия документа (PDF)

- `GET /v1/documents/{id}/digital.pdf` — PDF, сформированный заново по данным документа (не скан): заголовок
  (название схемы, номер и дата документа, если есть), поля «подпись — значение», таблицы схемы — настоящими
  таблицами, итоговые суммы; внизу служебная строка: «Цифровая версия, сформирована DocFlow по скану от
  ДД.ММ.ГГГГ. Статус: проверен / требует проверки». Доступно для `ok` и `needs_review`; иначе 409.
  Чужой документ — 404.
- Подписи полей: у `FieldSpec`/`ColumnSpec` появляется необязательное `title`; без него — `name` в читаемом виде
  («supplier_inn» → «Supplier inn» не годится: для встроенных схем (счёт, УПД, паспорт) прописать `title`
  по-русски; для схем без `title` — `name`).
- Числа — с пробелами тысяч и запятой («12 500,50»), даты — ДД.ММ.ГГГГ, булевы — «да/нет», пустые — «—».
- Шрифт DejaVu Sans (в образе уже есть `fonts-dejavu-core`); путь настраивается, для тестов — поиск в системе
  или пропуск теста, если шрифта нет.
- Кабинет: на странице документа кнопка «Цифровая версия (PDF)» рядом со «Скан (PDF)».
- Вебхук/API: в `document_payload` поле `digital_pdf_url` (когда доступно).

## Адаптивность

- Шапка публичных страниц на 320 px не должна вылезать за экран (сейчас на 37 px).
- Проверка на 320, 375, 414, 768, 1024, 1280, 1440, 1920: без горизонтальной прокрутки страницы.
