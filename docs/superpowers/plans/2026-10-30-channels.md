# Каналы приёма, автоопределение типа, тарифы: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** документы приходят в DocFlow через собственного Telegram-бота компании и почтовый ящик, тип определяется
автоматически, страницы считаются по тарифу, regex-проверки защищены таймаутом, тесты сайта идут в CI.

**Architecture:**
- Приём выносится из `api/documents.py` в сервис `docflow/intake.py`. Им пользуются API, бот и почта. Там же лимит тарифа.
- Новый процесс `docflow channels` (`docflow/channels/`): long polling ботов и опрос IMAP. Он только создаёт
  документы, распознаёт как обычно воркер.
- Автоопределение — шаг `_run` в конвейере: новый метод `classify` у экстрактора тенанта, поэтому локальный режим
  физически не ходит в облако.
- Ответы в бот — строки `exports` с `bot_chat_id` и назначениями `bot_ready`/`bot_reviewed`. Повторы и `requeue`
  общие с коннекторами, одна попытка = один вызов Bot API.
- Веб: чистые модули в `web/src/lib/` с тестами `node --test`, страницы `/app/bot` и `/app/mail`, блок тарифа.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy async, Alembic, arq, httpx (`MockTransport`), `imaplib`, пакет
`regex`, Next.js 15 / React 19, Node 22 в CI (`node:test`, type stripping).

**Spec:** `docs/superpowers/specs/2026-10-30-channels-design.md`

## Global Constraints

- Коммиты без `Co-Authored-By` и без «Generated with Claude Code».
- Только синтетические данные. Токены в тестах вымышленные, например `123456:AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA`.
- `.env`, секреты, пароли демо и ключи API не читать вслух, не печатать в отчёты, не сохранять в файлы.
- Стиль и плотность комментариев как в окружающем коде. Тексты для людей по-русски, идентификаторы по-английски.
  `ruff check src tests` чист (line-length 120).
- Существующие тесты остаются зелёными. Меняются только тесты, названные в задаче.
- **На машине мало памяти.** `pytest` — по одному запуску за раз, на переднем плане, только на файлы задачи. Никаких
  параллельных и фоновых прогонов, никаких `-n`. Весь набор — только в задаче 15, один раз.
- Команды:
  - `.venv/Scripts/python.exe -m pytest -q <файлы>`, `.venv/Scripts/ruff.exe check src tests`;
  - зависимости Python — через `uv` (в venv нет pip; Docker собирает с `uv sync --frozen`, поэтому `uv.lock` обязан
    обновиться);
  - в `web/`: `npm test`, `npm run lint`, `npm run build`. Кэш npm остаётся на E:.
- Postgres — только compose на `127.0.0.1:55432`. Нативный `127.0.0.1:5432` не трогать.
- Токен бота и пароль ящика никогда не попадают в ответ API, лог, текст ошибки, `last_error`, `Export.last_error` и
  кабинет. Исключения httpx и imaplib наружу не пробрасываются (`from None`), в сообщение — только тип исключения.
- Тексты из спеки — дословно:
  - `этот бот уже подключён к другому кабинету` (409), `Telegram не принял токен` (422);
  - `Попросите ссылку у администратора кабинета`, `Готово, присылайте документы`, `Пришлите фото или PDF документа`;
  - `Принял, распознаю (N стр.)`, `Нужна проверка`, `токен больше не действует`;
  - `Не удалось определить тип документа`, `Определяется…`, `Определить автоматически`, `Распознать заново`;
  - `Лимит страниц на месяц исчерпан (N из M)` (402), `напишите нам, чтобы сменить тариф`;
  - `проверка по шаблону не уложилась во время`.
- Тарифы: `trial` Пробный 50, `start` Старт 500, `business` Бизнес 3000, `unlimited` Без лимита — без лимита.
- Период учёта — календарный месяц по Москве. Slug автоопределения — `auto`, версия в документе до определения — `0`.
- Модель определения типа по умолчанию — `claude-haiku-5-5` (`DOCFLOW_ANTHROPIC_CLASSIFY_MODEL`).
- Не цели: вебхук Telegram, общий бот, ответные письма, разбиение пачки, оплата в продукте, разговорный бот.

## Review Focus

1. **В поле токена вставили мусор: перевод строки, пробел, `/../`, `?x=`.** Токен идёт в путь URL Bot API. Ожидание:
   обрезать пробелы, при неверном формате 422 без единого запроса наружу. Тест: задача 7,
   `test_connect_malformed_token_no_request`.
2. **Альбом приехал двумя порциями `getUpdates` или процесс перезапустили посреди альбома.** Ожидание: один документ,
   страницы по порядку, ничего не потеряно. Тесты: задача 8, `test_album_split_across_polls`,
   `test_restart_mid_album_no_loss`.
3. **Бот в рабочей группе, где люди переписываются.** Ожидание: на текст, стикеры и служебные сообщения молчит, не
   отвечает «Пришлите фото» на каждую реплику. Группа стала супергруппой — привязка не теряется. Тесты: задача 8,
   `test_group_text_silent`, `test_group_migration_keeps_link`.
4. **В ящике тысяча непрочитанных, письмо на 300 МБ, логотип в подписи письма.** Ожидание: память не забита, за проход
   не больше 20 новых писем, большое письмо не скачивается, логотип не становится страницей. Тесты: задача 10,
   `test_oversized_letter_not_fetched`, `test_pass_cap`, `test_inline_logo_ignored`.
5. **Модель упала с сырой английской ошибкой.** `document.error` содержит текст SDK. Ожидание: в чат уходит причина
   по-русски без сырого текста. Тест: задача 9, `test_failed_reply_hides_raw_model_error`.

```python
class IntakeError(Exception):              # .message — русский текст для человека

@dataclass(frozen=True)

    name: str
    read: Callable[[int], Awaitable[bytes]]  # read(лимит в байтах): лениво, чтобы повтор не качал файл заново

@dataclass(frozen=True)
class IntakeResult: document: Document; created: bool

async def find_by_idempotency_key(session, tenant_id, key) -> Document | None

) -> IntakeResult
```

```python
class BotPoller:
    def __init__(self, deps: ChannelDeps, bot_id: UUID, http: httpx.AsyncClient, clock=time.monotonic): ...
    async def poll_once(self, timeout: int = 25) -> None   # один getUpdates и его обработка
    async def run(self) -> None                            # цикл до отмены или отзыва токена
```

Постоянные: `ALBUM_WAIT = 2.0`, `DOWNLOAD_RETRIES = 5`, `IDEMPOTENCY`:
`tg:{bot_id}:{chat_id}:{message_id}` и `tg:{bot_id}:{chat_id}:album:{media_group_id}`. `source="telegram"`,

сообщения). Режим скана `gray`.

Алгоритм `poll_once`:
1. `offset` — из БД при старте, далее в памяти. Есть незавершённые альбомы → `timeout=0`.
2. Для каждого `update` не из `self._seen`: часть альбома → в буфер; иначе обработать сообщение.
3. Альбомы, чья последняя часть пришла `ALBUM_WAIT` назад и раньше, собрать: части по `message_id`, один документ.
4. Новый `offset`: есть незавершённые альбомы → наименьший `update_id` их частей; иначе `max(update_id) + 1`. Сохранить
   условным `UPDATE` **после** обработки. `_seen` чистить до `offset`. Повторная выдача обновлений, пока альбом ждёт,
   отсекается `_seen`, а после перезапуска — идемпотентностью.
5. `BotTokenRevoked` → `active=False`, `last_error = "токен больше не действует"`, выход из `run`. `BotConflict` →
   `last_error`, пауза. Прочие сбои опроса → `last_error`, пауза с ростом от 5 до 60 с.

Обработка сообщения по порядку:
- `migrate_to_chat_id` → обновить `BotChat.chat_id`, выход.
- `/start` (`^/start(@(\w+))?(?:\s+(\S+))?`): упомянут другой бот → молчим. Код сошёлся (`secrets.compare_digest`) → upsert
  чата, ответ `Готово, присылайте документы. Компания: «{tenant.name}»`. Код не сошёлся или его нет: чат не привязан →
  `Попросите ссылку у администратора кабинета`; чат привязан и кода нет → `Этот чат уже подключён, присылайте документы`.
- Чат не привязан → полное молчание, без `getFile`.
- Файлы: `photo` — наибольший по `width*height`; `document` с MIME или расширением JPEG, PNG, WEBP, TIFF, HEIC/HEIF, PDF.
- Файла нет:

  - `IntakeError` → `exc.message` реплаем;

Проход `MailboxPoller.poll` (IMAP в `asyncio.to_thread`):
1. `check_host`, расшифровать пароль, подключиться. Логин не принят (в том числе `UnicodeError`) → `active=False`,
   `last_error = "Почта не приняла логин или пароль"`, стоп. Сеть → `last_error = NETWORK_ERROR`
   (`Не удалось подключиться к почте`), `active` не меняется. Удачный вход снимает только `NETWORK_ERROR`.
2. `unseen_uids`, минус память `self._skipped[mailbox_id]`, не больше `MAX_LETTERS_PER_PASS`.
3. Письмо больше `max_request_mb` → не качать, `mark_seen`, `last_error = Письмо «…» больше N МБ`.
4. `parse_letter`. Чужой отправитель или нет подходящих вложений → письмо не трогаем, остаётся непрочитанным, uid в память
   `_skipped`, чтобы не качать каждую минуту. После перезапуска процесса такое письмо разбирается ещё раз и снова
   пропускается.
5. Каждый PDF — документ, все картинки вместе — один документ, по порядку вложений. Тип: `match_doc_type(subject_for_match(subject), types)`,
   иначе `default_schema`, иначе `AUTO_SLUG`. `source="email"`, `source_ref={"message_id": …, "attachment": "pdf:0" | "images"}`.
   Ключ: `mail:{mailbox_id}:{sha256(message_id или raw)}:pdf:{n}` или `:images`.
6. Исходы:
   - все приняты → `mark_seen`, `last_error=None`;
   - `IntakeLimitExceeded` → `mark_seen`, `last_error = exc.message`;
   - прочие постоянные `IntakeError` (`Invalid`, `TooLarge`, `Unsupported`) → `mark_seen`, `last_error = Письмо «…»: {message}`;
   - `IntakeStorageFailed`, `IntakeEnqueueFailed` → **не** `mark_seen`, следующий проход повторит, идемпотентность
     отсечёт уже принятые.
7. `last_checked_at = now`. Сбой одного письма не прерывает проход. Тема в `last_error` — через `one_line`, обрезка до 500.
