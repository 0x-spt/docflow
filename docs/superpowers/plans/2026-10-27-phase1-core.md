# DocFlow, фаза 1 «Ядро»: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** API, которое принимает фото или PDF документа и асинхронно возвращает PDF-скан с текстовым слоем, данные по схеме документа, результат проверок и вебхук.

**Architecture:** FastAPI принимает файлы и кладёт задачу в Redis (arq). Воркер прогоняет конвейер: подготовка страниц → PDF + OCR → извлечение VLM по JSON Schema, собранной из схемы документа → проверки → запись в Postgres → вебхук. Внешние зависимости (модель, OCR, хранилище) скрыты за протоколами, поэтому все юнит-тесты идут без сети и Docker.

**Tech Stack:** Python 3.12, uv, FastAPI, Pydantic v2, pydantic-settings, SQLAlchemy 2 async + asyncpg/aiosqlite, Alembic, arq, Redis 7, PostgreSQL 16, MinIO (boto3), OpenCV, Pillow, pillow-heif, pypdfium2, img2pdf, OCRmyPDF + Tesseract, anthropic SDK, httpx (Ollama, вебхуки), PyYAML, pytest + pytest-asyncio, ruff.

**Spec:** `docs/superpowers/specs/2026-10-27-docflow-design.md`

## Global Constraints

- Python `>=3.12`, пакет `docflow` в `src/docflow`, запуск через `uv run`.
- Комментарии и сообщения для людей на русском, идентификаторы на английском. Стиль комментариев как в `helios-naryady`: объясняют «зачем», а не «что».
- Модель по умолчанию `claude-opus-5-5`, effort `high`; `max_tokens=16000`; структурированный вывод через `output_config={"format": {"type": "json_schema", "schema": ...}}`; серверный fallback `betas=["server-side-fallback-2026-07-01"]`, `fallbacks="default"` через `client.beta.messages.create`.
- Локальная модель по умолчанию `qwen2.5vl:7b` через Ollama `http://localhost:11434`.
- Картинка для модели не больше `1568` px по длинной стороне, JPEG quality `90` (значения из Helios).
- Входные форматы: JPEG, PNG, WEBP, HEIC/HEIF, TIFF, PDF. Лимиты: `20` МБ на файл, `30` страниц на документ.
- Ключи API хранятся только как SHA-256-хэш; в ответах ключ показывается один раз при создании.
- Подпись вебхука: заголовок `X-DocFlow-Signature: sha256=<hex HMAC-SHA256(secret, body)>`, заголовок `X-DocFlow-Event`; ретраи с задержками `10, 60, 300, 1800, 7200` секунд, затем `failed`.
- Коммиты без `Co-Authored-By` и без строк «Generated with Claude Code».
- `ruff check` и `pytest` зелёные после каждой задачи.

## Review Focus

1. **Многостраничный документ** (УПД на 2 листах, 3 фото): страницы идут в PDF и в модель в порядке загрузки, результат один. → тест в Task 10.
2. **Фото с телефона**: поворот в EXIF и HEIC с iPhone должны дать ровную страницу, а не 415 и не боковой скан. → тесты в Task 4.
3. **Мусор на входе** (txt под видом jpg, пустой файл, 25 МБ, 31 страница): понятная ошибка 4xx при загрузке, воркер не падает. → тесты в Task 11.
4. **Русские форматы чисел и дат от модели** (`"12 500,00"`, `"01.02.2026"`, `"1,5 т.р."` уже приведённое моделью): нормализация до типа поля, а если не вышло, то `null` + issue, а не исключение. → тесты в Task 6.
5. **Повторная загрузка**: тот же `Idempotency-Key` возвращает тот же документ и не шлёт второй вебхук; отказ модели (`refusal`, `max_tokens`) даёт `failed` с причиной. → тесты в Task 10 и Task 11.
