# Подключения к системам клиента

Как подключить DocFlow к Google Таблицам, Битрикс24, amoCRM, 1С (OData), Telegram и почте: где взять ключи и что
вписать в форму. Подключения создаёт владелец (роль `owner`) в кабинете: **Подключения → Добавить**.

## Как это работает

1. **Подключение** — одна запись «куда»: система, адрес, ключи. Секреты (токены, пароли, JSON-ключ) хранятся
   зашифрованными и обратно не показываются; поле секрета в форме можно только заменить.
2. **Кнопка «Проверить подключение»** проверяет доступ, ничего не записывая в систему клиента.
3. **Правила** (кабинет → Правила) решают, какой документ куда уходит: «если условия — выгрузить в … /
   уведомить …». **Без правил ничего не выгружается и не отправляется.**
4. **Когда уходит.**
   - Выгрузка в 1С, CRM и таблицы — только для документа в статусе `ok` (все проверки пройдены или документ
     подтверждён оператором). Документ «на проверку» (`needs_review`) в учётную систему не попадает; после
     подтверждения оператором он становится `ok` и уходит.
   - Уведомление «Новый документ» — когда документ стал `ok`; «Нужна проверка» — когда документ попал на
     проверку (в тексте причины).
5. **Согласование.** Галочка правила «Требовать согласования» (документ сначала проверит человек, и только потом он
   уйдёт в системы): документ остановится на проверке с замечанием «нужно согласование: <название правила>», а
   после подтверждения оператором выгрузится.
6. **Повторы.** При временном сбое (система недоступна, ограничение запросов) доставка повторяется сама через
   10 с, 1 мин, 5 мин, 30 мин, 2 ч; потом статус «Ошибка» с причиной на русском. Постоянные ошибки (неверный ключ,
   нет прав) повторов не получают.
7. **Журнал.** В карточке документа блок «Выгрузки»: куда, что (Выгрузка / Уведомление о проверке / Уведомление о
   новом), статус (В очереди / Отправлено / Ошибка), ID созданной записи в системе клиента. Для «Ошибка» владелец
   нажимает «Повторить» после исправления причины.
8. **Защита от дублей.** Один документ в одно подключение уходит один раз; повторная постановка и «Повторить»
   находят уже созданную запись (строку, сделку, документ) и новую не создают.
9. **Реестр в Excel.** Без всяких подключений: на главной странице кабинета форма «Реестр в Excel» (тип документа,
   период, статус «Готовые» / «На проверке» / «Все»), либо API `GET /v1/exports/excel?schema=<slug>&from=ГГГГ-ММ-ДД&to=ГГГГ-ММ-ДД&status=ok`.
   Файл с листами «Документы» и «Позиции»; больше 5000 документов за раз — ошибка 422, сузьте период.

## Ключ шифрования секретов (для администратора сервера)

Секреты подключений шифруются ключом `DOCFLOW_SECRETS_KEY` (Fernet). Без него подключение сохранить нельзя
(«на сервере не настроен ключ шифрования (DOCFLOW_SECRETS_KEY)»).

Сгенерировать:

```
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Результат — в `.env` на сервере: `DOCFLOW_SECRETS_KEY=<ключ>`, затем `docker compose up -d`. Правила:

- ключ не коммитьте и не пересылайте; `.env` в репозитории игнорируется. Свой ключ у каждого стенда;
- потеряли или сменили ключ — старые секреты не расшифруются («секреты получателя не расшифровываются: ключ
  шифрования изменился»). Решение: ввести секреты заново. В API это `PATCH /v1/destinations/<id>` с полным
  набором `secrets`; в кабинете — «Заменить» у каждого секретного поля;
- ключ не строка «как придумали»: только вывод команды выше, иначе «ключ шифрования DOCFLOW_SECRETS_KEY
  некорректен».

## Google Таблицы

Что нужно: сервисный аккаунт Google и таблица.

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте проект (или выберите свой).
2. **API и сервисы → Библиотека** → найдите **Google Sheets API** → «Включить».
3. **IAM и администрирование → Сервисные аккаунты → Создать сервисный аккаунт** (имя любое, роли не нужны).
4. Откройте созданный аккаунт → **Ключи → Добавить ключ → Создать новый ключ → JSON**. Скачается файл.
5. В файле скопируйте значение `client_email` (вида `имя@проект.iam.gserviceaccount.com`).
6. Откройте таблицу Google → **Настройки доступа** → добавьте этот email с ролью **Редактор**.
7. В кабинете: Подключения → Google Таблицы:
   - **Таблица** — ссылка на таблицу или её ID (часть ссылки между `/d/` и `/edit`);
   - **Лист документов**, **Лист позиций** — необязательно; по умолчанию «Документы» и «Позиции», создаются сами;
   - **Ключ сервисного аккаунта (JSON)** — содержимое скачанного файла целиком.
8. «Проверить подключение» — должно ответить «Таблица «…» доступна».
9. Ниже выберите схему документа и отметьте поля, которые пойдут в таблицу (название колонки можно не задавать:
   возьмётся название поля; если не отметить ни одного, выгружаются все поля схемы).

Поведение: каждый документ — строка на листе документов, каждая позиция — строка на листе позиций (в первой
колонке id документа; по нему находятся повторы). Шапку создаём, если лист пустой; существующую шапку не трогаем.
Значения из документов записываются как текст: то, что начиналось бы с `=`, `+`, `-`, `@`, формулой не станет.
Даты и числа записываются как даты и числа Таблиц.

## Битрикс24

1. На портале: **Приложения → Разработчикам → Другое → Входящий вебхук** (нужны права администратора портала).
2. Права вебхука: **CRM (crm)**. Сохраните.
3. Скопируйте «Пример URL для вызова REST» без имени метода — адрес вида
   `https://портал.bitrix24.ru/rest/1/ключ/`. Он содержит ключ, поэтому хранится как секрет.
4. В кабинете: Подключения → Битрикс24:
   - **Входящий вебхук** — этот адрес;
   - **Ответственный (ID)** — ID сотрудника (число из ссылки на его профиль); пусто — владелец вебхука;
   - **Воронка (ID)** — пусто для воронки по умолчанию;
   - **Стадия** — код стадии, например `NEW` или `C2:NEW` (для второй воронки); пусто — первая стадия воронки;
   - **Контрагент** — `supplier` (для входящих счетов и УПД: компания поставщика) или `buyer` (покупатель).
5. «Проверить подключение»: «Портал доступен, пользователь …».
6. Сопоставление полей: поле документа → код пользовательского поля карточки (только `UF_CRM_…`). Не указанные
   поля не выгружаются.

Что создаётся: компания (ищется по ИНН в реквизитах, иначе по названию; новой добавляется реквизит с ИНН/КПП),
сделка с `ORIGINATOR_ID=docflow` и `ORIGIN_ID=<id документа>`, комментарий в ленте сделки со ссылками на
цифровой PDF, скан и документ в кабинете.

## amoCRM

1. В amoCRM: **amoMarket → Создать интеграцию** (внешняя интеграция, «Только для вашего аккаунта»).
2. Раздел **Ключи и доступы** интеграции → **Долгосрочный токен**: срок выберите максимальный, права — на
   сделки и компании (с чтением и записью). Скопируйте токен (показывается один раз).
3. В кабинете: Подключения → amoCRM:
   - **Поддомен** — `company` или `company.amocrm.ru` (Kommo: `company.kommo.com`);
   - **Долгосрочный токен** — токен;
   - **Воронка (ID)**, **Этап (ID)**, **Ответственный (ID)** — числа. ID воронки и этапа видны в настройках
     воронки (в amoCRM — в адресе `…/leads/pipeline/<id>` и при наведении на этап в настройках) или в ответе
     `https://<поддомен>.amocrm.ru/api/v4/leads/pipelines` (откройте под своим пользователем). ID ответственного —
     в `…/api/v4/users`. Пусто — воронка по умолчанию, первый этап, владелец токена;
   - **Поле ИНН у компании (ID)** — числовой ID пользовательского поля компании «ИНН»
     (`…/api/v4/companies/custom_fields`). Без него компании ищутся по названию;
   - **Контрагент** — `supplier` или `buyer`.
4. «Проверить подключение»: «Аккаунт «…» доступен».
5. Сопоставление: поле документа → числовой ID пользовательского поля сделки.

Создаётся сделка с компанией и примечание со ссылками на PDF. В конце названия сделки стоит метка
`docflow<12 символов id>`, по ней находится повтор.

Известное ограничение: поиск уже созданной сделки идёт через поиск amoCRM, а он обновляется не мгновенно. Если
повтор прилетел сразу после сбоя, а поиск ещё не видит сделку, возможна вторая сделка с той же меткой —
удалите лишнюю вручную.

## 1С (OData)

Подходит 1С:Предприятие 8.3 с публикацией на веб-сервере (Бухгалтерия предприятия 3.0 по умолчанию; УТ 11 и ERP
— с поправкой ниже). Настройку делает администратор 1С.

1. **Публикация.** Конфигуратор: **Администрирование → Публикация на веб-сервере**, флажок **«Публиковать
   стандартный интерфейс OData»**. Проверьте в браузере `https://<адрес>/<база>/odata/standard.odata/$metadata`
   — придёт XML.
2. **Состав объектов.** Откройте в базе обработку **«Настройка автоматического REST-сервиса»** (в 1С, 1cfresh —
   в разделе администрирования) и включите: `Catalog_Контрагенты`, `Catalog_Номенклатура` и документ — для
   поступления `Document_ПоступлениеТоваровУслуг` (вместе с табличной частью «Товары»), для реализации
   `Document_РеализацияТоваровУслуг`. Для таблицы организаций в браузере (шаг 4) нужен ещё `Catalog_Организации`, но самой выгрузке он не требуется. Нужных объектов нет — получите
   «в публикации OData нет объектов: …».
3. **Пользователь.** Заведите пользователя 1С с правами на чтение и запись этих объектов. Лучше отдельного, не
   администратора.
4. **Ref_Key организации.** Откройте в браузере
   `<адрес публикации>/odata/standard.odata/Catalog_Организации?$format=json&$select=Ref_Key,Description` и
   скопируйте `Ref_Key` нужной организации (GUID вида `1a2b3c4d-…`). Так же — склад (`Catalog_Склады`), договор
   (`Catalog_ДоговорыКонтрагентов`), валюта (`Catalog_Валюты`). Нужен GUID, а не название.
5. **В кабинете: Подключения → 1С (OData):**
   - **Адрес публикации 1С** — например `https://1c.example.ru/base` (с `/odata/standard.odata` на конце или без;
     логин и пароль в адресе не указывать);
   - **Организация (Ref_Key)** — обязательно;
   - **Вид документа** — `purchase` (Поступление товаров и услуг: входящие счета, УПД, накладные, контрагент —
     поставщик) или `sale` (Реализация: контрагент — покупатель);
   - **Склад**, **Договор**, **Валюта** (Ref_Key) — необязательно; пусто — заполнит бухгалтер;
   - **Ставка НДС** — `НДС22` (по умолчанию), `НДС20`, `НДС10`, `НДС0`, `БезНДС`;
   - **Вид операции** — по умолчанию «Товары»;
   - **Объект документа**, **Справочник контрагентов**, **Справочник номенклатуры** — только если имена
     нетиповые;
   - **Имена реквизитов** — для нетиповых конфигураций строки `Стандартное=Своё`, по одной на строку;
   - секреты: **Пользователь 1С** и **Пароль**.
6. **УТ 11 и ERP.** Там флаг НДС называется иначе — добавьте в «Имена реквизитов» строку
   `СуммаВключаетНДС=ЦенаВключаетНДС`. Проверка подключения подскажет это сама, если у документа нет реквизита.
7. «Проверить подключение»: «Публикация 1С доступна, объекты найдены».
8. Сопоставление (необязательно): какое поле документа считать наименованием контрагента, ИНН, КПП, номером и
   датой входящего документа и колонками позиций (наименование, количество, цена, сумма, сумма НДС, сумма с
   НДС).

Что делает выгрузка:

- Контрагент ищется по ИНН (с подходящим КПП, если их несколько), без ИНН — по точному наименованию; не найден — создаётся.
- Номенклатура **должна существовать**: ищется по точному наименованию (запасной вариант — единственное близкое по вхождению), не найденные не создаются. Ошибка «в 1С нет
  номенклатуры: …» — заведите позиции или добавьте сопоставление.
- Документ создаётся **непроведённым** с комментарием `DocFlow <метка>` и ссылкой на кабинет; бухгалтер
  проверяет, при необходимости нажимает «Заполнить счета учета» и проводит сам.
- Повтор находит документ по метке в комментарии и не создаёт второй.
- Нет позиций — создаётся документ с суммой и пометкой «позиции не распознаны».

Что проверить на живой базе перед запуском в работу (мы тестировали на заглушках, не на вашей конфигурации):
1) прошла ли «Проверить подключение»; 2) выгрузка тестового документа и его вид в 1С; 3) корректность НДС и
суммы документа; 4) работу поиска контрагента и номенклатуры на реальных наименованиях; 5) что документ
действительно остаётся непроведённым.

## Telegram

1. В Telegram откройте **@BotFather** → `/newbot` → имя и username бота → получите **токен** вида
   `123456:ABC…`.
2. Добавьте бота в нужный чат; в канал — администратором с правом публикации. Для личных сообщений напишите
   боту первым (иначе он не может вам писать).
3. **chat_id.** Для канала можно указать `@имя_канала`. Для чата и группы: напишите в нём любое сообщение, откройте
   `https://api.telegram.org/bot<токен>/getUpdates` и найдите `"chat":{"id":…}` (у групп число с минусом, у
   супергрупп вида `-100…`).
4. В кабинете: Подключения → Telegram: **Чат** — chat_id или `@имя`; **Токен бота** — токен.
5. «Проверить подключение»: «Бот @… доступен, чат «…» найден».

Тексты уведомлений:

```
Нужна проверка: <тип документа> № 123 от 05.10.2026
Причины: <замечания проверок, до нескольких штук, «и ещё N»>
<ссылка на документ в кабинете>
```

```
Новый документ: <тип документа> № 123 от 05.10.2026
<контрагент>, сумма 12 345,00 ₽
<ссылка на документ в кабинете>
```

## Почта (SMTP)

В кабинете: Подключения → Почта.

- **SMTP-сервер** — имя хоста, например `smtp.yandex.ru` (без `http://` и порта; хост должен быть публичным);
- **Порт** — пусто: 587 (STARTTLS); для SSL обычно 465;
- **Защита соединения** — `starttls` (по умолчанию), `ssl` или `none`. Вход по логину и паролю без шифрования
  запрещён: при `none` с логином отправка запрещена («вход без шифрования запрещён — выберите starttls или ssl»);
- **Адрес отправителя**, **Получатели** (через запятую, не больше 20) — только латиница;
- секреты: **Логин** (пусто, если сервер вход не требует) и **Пароль**. Для Яндекса и Gmail нужен **пароль
  приложения**, а не основной пароль аккаунта: создаётся в настройках безопасности почты.

Письма отправляются с теми же текстами, что и в Telegram.

## Правила: примеры

Кабинет → Правила. Условия правила выполняются все сразу (И); действия сработавших правил складываются.
Операции условий: равно, не равно, больше, больше или равно, меньше, меньше или равно, содержит, есть в
справочнике, пусто, не пусто.

1. **УПД от поставщика → 1С.** Схема: УПД (или «Любой»); условий нет; «Выгрузить в»: 1С (OData). Все готовые УПД
   уходят в 1С.
2. **Сумма больше 500 000 → согласование.** Условие: поле итоговой суммы вашей схемы больше `500000`; галочка
   «Требовать согласования»; «Выгрузить в»: 1С. Такой документ сначала проверит человек и после подтверждения
   уйдёт в 1С.
3. **На проверку → Telegram оператору.** В «Уведомить» выберите Telegram — уведомление «Нужна проверка» придёт,
   когда документ попадёт на проверку; «Новый документ» — для готовых. Одно правило с уведомлением на все
   документы нужного типа.
4. **Все счета → таблица и CRM.** Одно правило: «Выгрузить в» Google Таблицы и Битрикс24 одновременно.

## Если выгрузка не прошла

Причина показана в блоке «Выгрузки» документа (статус «Ошибка»). Исправьте и нажмите «Повторить».

| Сообщение | Что делать |
|---|---|
| документ не подтверждён (статус …): в учётную систему не выгружается | Подтвердите документ в проверке; выгрузка пойдёт после этого |
| получатель отключён | Включите подключение |
| на сервере не настроен ключ шифрования (DOCFLOW_SECRETS_KEY) | Администратору: задать ключ (раздел выше) |
| секреты получателя не расшифровываются: ключ шифрования изменился | Ввести секреты заново (раздел выше) |
| внешняя система не ответила вовремя | Временно, повтор будет сам; если повторяется — проверьте доступность системы клиента |
